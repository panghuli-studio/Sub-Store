# 设计稿自查与实测

实测日期：2026-11-27。所有测试针对临时原型；不是生产服务的验收报告。

## 验证结果

- `npm run build` 成功；Vue 模板及资源编译完成，输出脚本约 260KB，压缩约 83KB。原型没有接入产品 lint、类型检查或 CI，不能把编译成功当作正式工程门禁通过。
- 本机 Chromium 的八页 × 375/1280px × 深浅主题共 32 组合截图与几何测量，没有横向溢出。375px 的可执行图标按钮最小 44×44px。
- 本机 Chromium、Firefox、WebKit 均打开文件页并验证提示和弹层。真实浏览器截图已读取：桌面深色文件页、手机浅色文件页、八页深色缩略总览、手机文字菜单、浅色预览与深色日志弹层。
- 公网三个内核分别检查 32 个页面组合，共 96 次页面检查。其中 95 次返回 200，1 次 Chromium 订阅页遇到临时隧道 502；该次不能算原型页面通过。WebKit 最后一次复制提示定位请求也超时。没有把这些失败改记为通过。
- 切换到构建产物静态服务后，仅复测失败页面与提示、键盘行为，没有再次扩大完整矩阵。三个内核的订阅页均返回 200，标题为“订阅”；复制提示在 150ms 时未出现、400ms 时出现，Esc 后为 0 个、重新聚焦后为 1 个。日志弹层内只显示一个提示。数据见 `review/final-check.json`。

## 键盘与无障碍

提示和 `aria-label` 同源。只读按钮名称包含原动作和限制原因，并带 `aria-disabled=true`。成熟库生成唯一描述关联；原生 dialog 管理模态层。

在三个内核中，强制把焦点移到弹层外页面按钮均未成功；12 次 Tab 没有到达任何弹层外可交互元素。循环期间浏览器可能把 `activeElement` 记为 `BODY`，不能仅凭 `closest('dialog')` 为 false 就判断焦点逃逸。WebKit 在当前 Mac 键盘设置下，Tab 序列以 dialog/body 为主，没有验证到完整按钮遍历；真实 Safari 键盘偏好与完整操作序列仍需人工检查。Escape 关闭弹层已测。

## 限制与待确认

本轮没有逐一实现上游 227 处图标标签所在的所有源码分支；它展示六页和关键弹层的统一设计规则。批量归档选择、完整订阅加工编辑、真实后端错误、权限与令牌周期未逐项模拟。真实 Safari/iOS、触控手感、读屏器和色觉辅助检查未完成。

临时公网隧道可能出现 502 或超时，不提供持续可用保证。预览当前使用独立构建产物，只有示例数据，未暴露真实服务与配置。

待用户确认的是：是否采用“保留现有结构、补统一短提示、增加图标说明页和手机文字操作”的设计方向。确认设计后才进入产品工程接入与全量迁移。
